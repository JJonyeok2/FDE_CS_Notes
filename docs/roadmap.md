# 학습 로드맵

19개 주제를 한 번에 깊게 파려고 하면 끝나지 않는다. 세 바퀴로 나눠서 돈다.

## 1바퀴: 용어와 큰 그림 (주제당 하루)

각 문서의 "개념 요약"만 읽고, 모르는 용어를 한 문장으로 설명할 수 있게 만든다. 이 단계의 목표는 면접에서 어떤 단어가 나와도 당황하지 않는 것이다.

1. 네트워크와 HTTP
1. API와 인증
1. 데이터베이스와 SQL
1. 데이터 통합
1. OS, 리눅스, 컨테이너
1. 클라우드와 배포
1. 보안과 권한
1. 시스템 설계 기초
1. LLM 응용
1. 자료구조와 알고리즘
1. 트러블슈팅 방법론
1. 고객 요구사항과 PoC
1. 테스트
1. 기업 업무 시스템: ERP, CRM, 그룹웨어
1. RAG와 벡터 DB 심화
1. Agentic Workflow와 멀티 에이전트
1. SDK와 AI 프레임워크
1. 데이터 파이프라인
1. 고객사와 산업 이해

## 2바퀴: 손으로 확인 (주제당 2~3일)

"현장에서 만나는 상황"에 나오는 명령과 시나리오를 직접 실행해 본다. 읽기만 한 지식은 면접 꼬리 질문에서 무너진다.

| 주제 | 직접 해 볼 것 |
| --- | --- |
| 네트워크 | `curl -v`, `dig`, `traceroute` 로 요청 한 건의 경로를 따라가기 |
| API와 인증 | OAuth 2.0 인가 코드 흐름을 Postman이나 curl로 단계별 재현 |
| 데이터베이스 | `EXPLAIN ANALYZE` 로 인덱스 유무에 따른 실행 계획 비교 |
| 데이터 통합 | CSV 두 개를 스키마가 다른 상태로 합치는 스크립트 작성 |
| 리눅스 | `top`, `df -h`, `journalctl`, `docker logs` 로 죽은 컨테이너 원인 찾기 |
| 클라우드 | 보안 그룹을 일부러 막아 놓고 타임아웃이 나는지 확인 |
| 보안 | JWT를 직접 디코딩해서 페이로드와 서명 구조 확인 |
| 시스템 설계 | 캐시를 붙이기 전후의 응답 시간 측정 |
| LLM 응용 | 청크 크기를 바꿔 가며 검색 결과가 어떻게 달라지는지 비교 |
| 알고리즘 | 유형별 대표 문제 3개씩 풀기 |
| 트러블슈팅 | 지난 버그 하나를 골라 다섯 단계(재현, 범위 좁히기, 가설, 검증, 기록)로 다시 써 보기 |
| 고객 요구사항 | 내 프로젝트 하나로 PoC 제안서(목표, 범위, 숫자로 된 성공 기준) 한 장 써 보기 |
| 테스트 | 내 프로젝트의 핵심 함수 하나에 pytest나 Vitest로 단위 테스트 3개 써 보기 |
| 기업 업무 시스템 | Salesforce나 HubSpot 무료 개발자 계정을 만들어 API로 고객 한 건을 조회해 보기 |
| RAG와 벡터 DB | 스캔 PDF 하나를 파싱해 결과를 눈으로 확인하고, 하이브리드 검색 전후의 검색 결과 비교하기 |
| Agentic Workflow | 같은 일을 고정 워크플로와 에이전트로 각각 만들어 성공률과 비용 비교하기 |
| SDK와 프레임워크 | 모델 API를 SDK 없이 HTTP로 한 번, SDK로 한 번 호출해 차이 보기 |
| 데이터 파이프라인 | 작은 데이터로 Bronze, Silver, Gold 세 단계 변환을 만들고 같은 날짜를 두 번 돌려 결과가 같은지 확인하기 |
| 고객사와 산업 | 지원 회사의 고객 산업 하나를 골라 사업보고서와 보도자료로 세 줄 요약(핵심 업무, 새는 곳, 첫 지점) 써 보기 |

## 3바퀴: 내 이야기로 만들기

각 문서의 "내 프로젝트와의 연결" 칸을 채운다. 아래 형식으로 쓴다.

> - **상황**: 어떤 프로젝트에서 무슨 문제가 있었는가
> - **원인**: 무엇이 원인이었고 어떻게 찾았는가
> - **해결**: 무엇을 바꿨는가
> - **결과**: 수치나 관찰 가능한 변화

이 칸이 채워진 문서는 그대로 면접 답변이 된다. 다 채웠으면 [면접 질문 모음](./interview-questions)의 질문에 소리 내어 답해 보며 마무리한다.

## 우선순위

시간이 부족하면 이 순서로 줄인다.

1. **반드시**: 1(네트워크), 2(API와 인증), 3(데이터베이스), 9(LLM 응용), 11(트러블슈팅), 12(고객 요구사항과 PoC), 15(RAG와 벡터 DB), 19(고객사와 산업)
2. **가능하면**: 4(데이터 통합), 6(클라우드), 7(보안), 14(기업 업무 시스템), 16(Agentic Workflow)
3. **여유 있을 때**: 5(리눅스), 8(시스템 설계), 10(알고리즘), 13(테스트), 17(SDK와 프레임워크), 18(데이터 파이프라인)

11번, 12번, 19번은 CS 지식은 아니지만 FDE 면접에서 가장 깊게 파고드는 부분이라 "반드시"에 넣었다. 19번은 지원하는 회사의 고객 산업에 맞춰 직접 내용을 보강한다. 지원하는 회사가 코딩 테스트를 본다면 10번을, 과제 전형이 있다면 13번을 앞으로 당긴다.
