# 5. OS, 리눅스, 컨테이너

> 한 줄 요약: 고객사 서버에는 화면이 없다. SSH로 들어가 터미널만으로 무슨 일이 벌어지는지 알아낼 수 있어야 한다.

## 개념 요약

### 프로세스와 스레드

- **프로세스**: 실행 중인 프로그램. 독립된 메모리 공간을 가진다.
- **스레드**: 프로세스 안의 실행 흐름. 메모리를 공유한다. 가볍지만 공유 데이터를 동시에 건드리면 문제가 생긴다.
- **컨텍스트 스위칭**: CPU가 실행 대상을 바꾸는 것. 비용이 든다.

### 동시성과 병렬성

- **동시성**: 여러 일을 번갈아 가며 진행한다. (코어 하나로도 가능)
- **병렬성**: 여러 일을 실제로 동시에 실행한다. (코어 여러 개 필요)
- **경쟁 상태**: 실행 순서에 따라 결과가 달라지는 버그. 락이나 원자적 연산으로 막는다.
- **데드락**: 서로가 가진 자원을 기다리며 영원히 멈춤.

### I/O 바운드와 CPU 바운드

- **I/O 바운드**(네트워크, 디스크 대기가 대부분): 비동기나 스레드가 효과적이다. API 서버, LLM 호출이 여기에 해당한다.
- **CPU 바운드**(계산이 대부분): 여러 프로세스로 나눠야 한다.
- 파이썬은 GIL 때문에 스레드로는 CPU 작업을 병렬로 못 한다. 그래서 I/O에는 `asyncio` 나 스레드, CPU 작업에는 `multiprocessing` 을 쓴다.

### 메모리

- **가상 메모리**: 프로세스마다 독립된 주소 공간을 준다.
- **스택과 힙**: 스택은 함수 호출과 지역 변수, 힙은 동적으로 할당한 객체.
- **메모리 누수**: 쓰지 않는 메모리가 해제되지 않고 쌓이는 것.
- **OOM Killer**: 메모리가 바닥나면 리눅스가 프로세스를 강제로 죽인다. "프로세스가 이유 없이 죽었다"의 흔한 원인이다.

### 파일 시스템과 권한

- 권한은 소유자, 그룹, 기타에 대해 읽기(r=4), 쓰기(w=2), 실행(x=1)으로 나타낸다. `chmod 644` 는 소유자 읽기와 쓰기, 나머지는 읽기만.
- `Permission denied` 를 만나면 `ls -l` 로 권한을, `whoami` 로 현재 사용자를 본다.

### 꼭 알아야 할 명령

| 목적 | 명령 |
| --- | --- |
| 지금 무엇이 돌고 있나 | `ps aux`, `top`, `htop` |
| 메모리 | `free -h` |
| 디스크 | `df -h`(전체), `du -sh *`(폴더별) |
| 포트를 누가 쓰나 | `ss -tlnp`, `lsof -i :8080` |
| 로그 보기 | `tail -f 파일`, `journalctl -u 서비스 -f` |
| 찾기 | `grep -r "문자열" .`, `find . -name "*.log"` |
| 네트워크 확인 | `curl -v`, `ping`, `dig`, `nc -zv 호스트 포트` |
| 서비스 관리 | `systemctl status / restart 서비스` |
| 환경 변수 | `env`, `echo $이름` |
| 원격 접속과 복사 | `ssh`, `scp`, `rsync` |

파이프(`|`)로 명령을 잇는 것에 익숙해져야 한다. 예: `grep ERROR app.log | sort | uniq -c | sort -rn | head`

### 종료 코드와 시그널

- 종료 코드 0은 성공, 그 외는 실패. 137은 SIGKILL(대개 OOM), 143은 SIGTERM.
- **SIGTERM**은 정리할 시간을 주는 종료 요청, **SIGKILL**은 즉시 강제 종료다.

### 컨테이너

- 컨테이너는 **격리된 프로세스**다. 가상 머신과 달리 호스트의 커널을 공유하므로 가볍고 빨리 뜬다.
- **이미지**는 실행에 필요한 모든 것을 담은 읽기 전용 꾸러미, **컨테이너**는 그 이미지를 실행한 것이다.
- "내 컴퓨터에서는 되는데"를 없애 준다. 고객사 환경에 배포할 때 특히 가치가 크다.

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "main.py"]
```

- 의존성 파일을 먼저 복사하는 이유: 레이어 캐시 때문이다. 코드만 바뀌면 의존성 설치 단계를 다시 하지 않는다.
- 컨테이너 안의 파일은 컨테이너가 사라지면 같이 사라진다. 남겨야 할 데이터는 **볼륨**에 둔다.
- 컨테이너 안에서 `localhost` 는 컨테이너 자신이다. 호스트나 다른 컨테이너의 서비스에 접근할 때 자주 틀린다.

| 목적 | 명령 |
| --- | --- |
| 실행 중인 컨테이너 | `docker ps` (죽은 것 포함은 `-a`) |
| 로그 | `docker logs -f 컨테이너` |
| 안으로 들어가기 | `docker exec -it 컨테이너 sh` |
| 자원 사용량 | `docker stats` |
| 여러 컨테이너 묶어 실행 | `docker compose up -d` |

### 쿠버네티스 한 줄 개념

컨테이너 여러 개를 여러 서버에 배치하고, 죽으면 다시 띄우고, 늘리고 줄이는 일을 자동으로 해 주는 도구다. Pod(컨테이너 묶음), Deployment(몇 개를 유지할지), Service(접근 주소) 정도의 용어를 안다.

## 현장에서 만나는 상황

### 상황 1: "서비스가 죽었어요"

1. 프로세스나 컨테이너가 살아 있는가: `systemctl status`, `docker ps -a`
2. 죽었다면 종료 코드와 마지막 로그: `docker logs --tail 100`, `journalctl -u 서비스 -n 100`
3. 디스크가 찼는가: `df -h` (로그 파일이 디스크를 다 채우는 일이 매우 흔하다)
4. 메모리가 부족했는가: `dmesg | grep -i "killed process"`
5. 포트 충돌인가: `ss -tlnp`
6. 최근에 무엇이 바뀌었는가: 배포, 설정 변경, 인증서 만료

- **고객에게 설명하는 말**: "로그 파일이 쌓여서 서버 저장 공간이 가득 찼고, 그래서 프로그램이 멈췄습니다. 오래된 로그를 자동으로 정리하도록 설정해 재발을 막겠습니다."

### 상황 2: "점점 느려지다가 재시작하면 괜찮아져요"

- 메모리 누수를 의심한다. 시간에 따른 메모리 사용량 추이를 본다.
- 열린 연결이나 파일 핸들이 닫히지 않고 쌓이는지 확인한다.

### 상황 3: 인터넷이 안 되는 서버에 설치해야 한다

- 폐쇄망(에어갭) 환경은 `pip install` 이나 `docker pull` 이 안 된다.
- 이미지를 파일로 저장해(`docker save`) 반입하고 불러온다(`docker load`). 의존성 패키지도 미리 받아 함께 가져간다.
- 반입 절차와 보안 검사에 걸리는 시간을 일정에 넣는다.

### 상황 4: 고객 서버 운영체제가 다르다

- 버전을 먼저 확인한다: `cat /etc/os-release`, `uname -a`
- 컨테이너로 배포하면 차이의 대부분이 사라진다.

## 면접 예상 질문

### Q. 프로세스와 스레드의 차이는 무엇인가요?

프로세스는 독립된 메모리 공간을 가진 실행 단위이고, 스레드는 한 프로세스 안에서 메모리를 공유하는 실행 흐름입니다. 스레드는 생성과 전환 비용이 낮지만 공유 자원 때문에 동기화 문제가 생길 수 있고, 프로세스는 서로 격리되어 안전하지만 통신 비용이 큽니다.

### Q. 컨테이너와 가상 머신의 차이는 무엇인가요?

가상 머신은 운영체제 전체를 가상화하고, 컨테이너는 호스트의 커널을 공유하면서 프로세스만 격리합니다. 그래서 컨테이너가 더 가볍고 빨리 시작됩니다. 대신 격리 수준은 가상 머신이 더 강합니다.

### Q. 서버가 느려졌을 때 무엇을 확인하시겠습니까?

CPU, 메모리, 디스크, 네트워크 네 가지 자원 중 어느 것이 병목인지 먼저 봅니다. `top` 으로 CPU와 메모리를, `df` 로 디스크를 확인하고 로그에서 오류나 느린 요청을 찾습니다. 그리고 최근 변경 사항이 있었는지 확인합니다.

### Q. 동시성과 병렬성의 차이는 무엇인가요?

동시성은 여러 작업을 번갈아 처리해 동시에 진행되는 것처럼 다루는 구조이고, 병렬성은 여러 코어에서 실제로 동시에 실행하는 것입니다. 외부 API 호출처럼 대기 시간이 긴 작업은 동시성만으로도 크게 빨라집니다.

### Q. 데드락은 무엇이고 어떻게 막나요?

둘 이상의 작업이 서로가 가진 자원을 기다리며 진행하지 못하는 상태입니다. 자원을 항상 같은 순서로 획득하게 하거나, 대기 시간 제한을 두어 예방합니다.
