# 10. 자료구조와 알고리즘

> 한 줄 요약: FDE 면접의 코딩 문제는 어려운 알고리즘보다 "실무와 닮은 문제를 깔끔하게, 설명하면서 푸는가"를 본다. 코딩 테스트 통과에 필요한 핵심만 정리한다.

## 개념 요약

### 시간 복잡도

입력이 커질 때 실행 시간이 얼마나 늘어나는가를 나타낸다.

| 표기 | 이름 | 예 | n이 10만일 때 |
| --- | --- | --- | --- |
| O(1) | 상수 | 해시 조회 | 즉시 |
| O(log n) | 로그 | 이진 탐색 | 약 17번 |
| O(n) | 선형 | 한 번 훑기 | 10만 번 |
| O(n log n) | 선형 로그 | 정렬 | 약 170만 번 |
| O(n²) | 제곱 | 이중 반복문 | 100억 번 (너무 느림) |

코딩 테스트의 감각: 1초에 대략 1억 번 연산. n이 10만이면 O(n²)은 안 되고 O(n log n) 이하여야 한다.

### 자료구조

| 자료구조 | 특징 | 파이썬 |
| --- | --- | --- |
| 배열 | 인덱스 조회 O(1), 중간 삽입 O(n) | `list` |
| 해시 테이블 | 조회, 삽입, 삭제 평균 O(1) | `dict`, `set` |
| 스택 | 나중에 넣은 것이 먼저 나옴 | `list` 의 `append`, `pop` |
| 큐 | 먼저 넣은 것이 먼저 나옴 | `collections.deque` |
| 힙 | 최솟값을 O(log n)에 꺼냄 | `heapq` |
| 트리 | 계층 구조 | 직접 구현 |
| 그래프 | 정점과 간선 | 인접 리스트(`dict` 의 `list`) |

**가장 중요한 것은 해시 테이블이다.** "이미 본 적 있는가", "몇 번 나왔는가", "짝이 있는가"를 묻는 문제는 대부분 `dict` 나 `set` 으로 O(n²)을 O(n)으로 줄인다. 실무에서도 두 데이터를 키로 맞추는 일은 전부 이것이다.

### 꼭 익혀야 할 패턴

**1. 해시로 세기와 찾기**

```python
from collections import Counter, defaultdict

counts = Counter(words)            # 빈도 세기
groups = defaultdict(list)         # 키별로 묶기
for row in rows:
    groups[row["customer_id"]].append(row)
```

**2. 정렬 후 처리**

```python
# 여러 기준 정렬: 금액 내림차순, 같으면 이름 오름차순
rows.sort(key=lambda r: (-r["amount"], r["name"]))
```

**3. 투 포인터와 슬라이딩 윈도**: 정렬된 배열이나 연속 구간을 다룰 때 쓴다. 이중 반복문을 한 번의 순회로 줄인다.

**4. 이진 탐색**: 정렬된 데이터에서 찾거나, "조건을 만족하는 최솟값"을 찾을 때 쓴다.

```python
import bisect
idx = bisect.bisect_left(sorted_list, target)
```

**5. BFS와 DFS**: 그래프나 격자를 탐색한다. 최단 거리(간선 가중치가 같을 때)는 BFS.

```python
from collections import deque

def bfs(graph, start):
    visited = {start}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        for nxt in graph[node]:
            if nxt not in visited:
                visited.add(nxt)
                queue.append(nxt)
    return visited
```

**6. 힙**: "상위 k개", "가장 작은 것부터 처리"에 쓴다.

**7. 동적 계획법**: 큰 문제를 작은 문제의 답으로 푼다. 점화식을 세우는 연습이 필요하다. FDE 면접에서는 비중이 낮은 편이다.

### FDE 면접 문제의 성격

일반 알고리즘 문제보다 다음과 같은 유형이 자주 나온다.

- **데이터 가공**: 로그나 CSV, JSON을 읽어 집계하고 변환한다.
- **문자열 파싱**: 형식이 지저분한 입력을 정리한다.
- **두 데이터 맞추기**: 키로 조인하고 불일치를 찾는다.
- **구간 처리**: 일정 겹침, 구간 병합.
- **요구 사항이 점점 추가되는 문제**: 처음 코드를 얼마나 고치기 쉽게 짰는지를 본다.

### 푸는 순서

1. **문제를 다시 말한다.** 입력과 출력의 예를 직접 든다.
2. **질문한다.** 입력 크기는? 빈 입력은? 중복은? 정렬되어 있는가?
3. **단순한 풀이부터 말한다.** 복잡도를 말하고 개선 방향을 제시한다.
4. **말하면서 작성한다.** 침묵은 감점이다.
5. **직접 예시로 따라가 본다.** 경계 조건(빈 값, 하나, 최대)을 확인한다.
6. **복잡도와 개선점을 말한다.**

FDE는 고객 앞에서 생각을 설명하는 직무다. 정답만큼 **과정을 소통하는 방식**이 평가된다.

### 코드 품질

- 변수와 함수의 이름을 의미 있게 짓는다.
- 함수를 작게 나눈다. 요구 사항이 추가될 때 드러난다.
- 예외 입력을 처리한다. 실제 데이터는 항상 지저분하다.

## 현장에서 만나는 상황

### 상황 1: 스크립트가 데이터가 늘자 끝나지 않는다

- 이중 반복문으로 두 목록을 비교하고 있는지 본다. 한쪽을 `dict` 로 만들면 O(n²)이 O(n)이 된다.

```python
# 느림: 주문마다 고객 목록 전체를 훑는다
for order in orders:
    for customer in customers:
        if customer["id"] == order["customer_id"]:
            ...

# 빠름: 고객을 키로 한 번만 정리해 둔다
customer_by_id = {c["id"]: c for c in customers}
for order in orders:
    customer = customer_by_id.get(order["customer_id"])
```

### 상황 2: 파일이 메모리에 안 올라간다

- 한 번에 다 읽지 않고 한 줄씩 또는 덩어리 단위로 처리한다. 가능하면 DB에 넣고 SQL로 처리한다.

### 상황 3: 중복 제거와 순서 유지

- `set` 은 순서를 보장하지 않는다. 순서가 필요하면 `dict.fromkeys(items)` 를 쓴다.

## 면접 예상 질문

### Q. 배열과 연결 리스트의 차이는 무엇인가요?

배열은 연속된 메모리에 저장되어 인덱스 접근이 O(1)이지만 중간 삽입과 삭제가 O(n)입니다. 연결 리스트는 각 원소가 다음 원소를 가리키는 구조라 위치를 알면 삽입과 삭제가 O(1)이지만 특정 위치를 찾는 데 O(n)이 걸립니다.

### Q. 해시 테이블은 어떻게 동작하나요?

키를 해시 함수로 숫자로 바꿔 그 위치에 값을 저장합니다. 그래서 평균 O(1)에 조회할 수 있습니다. 서로 다른 키가 같은 위치로 가는 충돌은 체이닝이나 개방 주소법으로 처리하며, 충돌이 많아지면 성능이 떨어지므로 크기를 늘려 다시 배치합니다.

### Q. 스택과 큐는 각각 어디에 쓰나요?

스택은 나중에 들어간 것이 먼저 나오는 구조로 함수 호출 관리, 되돌리기, 괄호 검사, 깊이 우선 탐색에 씁니다. 큐는 먼저 들어간 것이 먼저 나오는 구조로 작업 대기열과 너비 우선 탐색에 씁니다.

### Q. BFS와 DFS는 어떻게 다르고 언제 쓰나요?

BFS는 가까운 정점부터 차례로 방문하며 큐를 씁니다. 간선의 가중치가 같을 때 최단 경로를 찾습니다. DFS는 한 방향으로 끝까지 간 뒤 돌아오며 스택이나 재귀를 씁니다. 모든 경로를 탐색하거나 연결 여부를 확인할 때 씁니다.

### Q. 이 코드의 시간 복잡도는 얼마이고 어떻게 개선할 수 있나요?

반복문이 몇 겹인지와 각 단계 안에서 호출하는 연산의 비용을 함께 봅니다. 예를 들어 반복문 안에서 리스트에 `in` 을 쓰면 겉으로는 한 겹이어도 O(n²)입니다. 이 경우 리스트를 집합으로 바꾸면 O(n)이 됩니다.
